## 二、技术栈分析

- Markdown 问答集，四大主题：互联网 Java 高并发、分布式系统、高可用架构、海量数据处理
- 每题以「场景 → 问题 → 层层追问 → 答案要点」组织，还原真实面试追问链路
- 技术栈聚焦经典互联网架构：MQ（Kafka/RocketMQ）、Redis、MySQL 分库分表、ES、Dubbo、Zookeeper
- 提供 PDF/EPUB 离线版本与在线阅读站点（doocs.github.io/advanced-java）
- doocs 组织同时维护 leetcode 等其他学习仓库，交叉引流

## 三、核心功能特性

1. **追问式结构**：模拟面试官连环追问，训练「答完一层还有下一层」的深度
2. **场景驱动**：先给业务场景再给方案，比裸背结论更接近实战
3. **聚焦进阶题**：不碰基础八股，专门解决 3-5 年经验档口的难题
4. **中文原生**：表述贴合国内大厂面试口径
5. **许可明确**：CC-BY-SA 4.0，分享与再加工规则清晰

## 四、应用场景说明

- 中高级后端岗面试冲刺：与 [javaguide.md](javaguide.md) 搭配，前者打底、本项目攻坚
- 架构面试素材：高可用与分布式章节可直接映射到「你处理过最难的生产问题」类行为题
- 对 SRE 方向：MQ 积压、缓存雪崩、分库分表等场景题与线上故障诊断高度同构
- 注意：技术选型偏传统互联网栈，云原生（K8s/Service Mesh）内容需另找 [../fullstack-arch/kubernetes-production-best-practices.md](../fullstack-arch/kubernetes-production-best-practices.md) 补齐

## 五、个人评价

### 优势

1. 追问链路式组织是同类仓库中独有的设计，面试还原度高
2. 主题选择精准，全部是 3 年以上经验档口的高频难题
3. 维护活跃（最近提交 2026-08），社区纠错及时

### 不足

1. 技术栈偏传统（Dubbo/Zookeeper 等），云原生与 AI 基础设施覆盖少
2. 答案以要点罗列为主，部分条目缺乏原理推导，深究仍需查原始文档
3. CC-BY-SA 的传染性条款对商业二次分发有一定限制

### 评分理由

4 星：中文进阶面试的最佳追问式题库，扣分在技术栈的时代局限（⭐79.1k，截至 2026-08）。
